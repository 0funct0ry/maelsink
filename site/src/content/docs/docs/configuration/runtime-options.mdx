Every setting in maelsink can be configured four ways, layered from lowest to highest
precedence:

1. **Built-in defaults** — baked into the binary.
2. **`maelsink.yaml`** — a config file, path given via `-c/--config`.
3. **`MAELSINK_*` environment variables** — override the file.
4. **CLI flags** — override everything, only in effect for that invocation.

A value set at a higher layer always wins, regardless of what's set below it. For
example, a `--smtp-port` flag beats `MAELSINK_SMTP_PORT` beats a `port:` line under
`smtp:` in `maelsink.yaml` beats the built-in default of `1025`.

Environment variables follow one fixed convention: `MAELSINK_<SECTION>_<KEY>`, with dots
replaced by underscores and everything uppercased. For example, `smtp.max_message_size_mb`
becomes `MAELSINK_SMTP_MAX_MESSAGE_SIZE_MB`.

<Aside type="note">
`MAELSINK_SMTP_AUTH` (a space-separated list of `user:pass` pairs) is an exception: it's
env-only, parsed directly by the `serve` command, and has no YAML key or CLI flag. It's
intended for quick CI use — see [Password files](/maelsink/docs/configuration/password-files/).
</Aside>

## The table

Every row below is a complete key: its YAML path, type, default, environment variable,
and CLI flag (long and short form, where one exists).

### smtp

| Key | Type | Default | Env var | Flag |
|---|---|---|---|---|
