maelsink exposes a stable REST API under `/api/v1`, mounted on the dedicated
REST API port (default `9090`) and read-through on the Web UI port (default
`8080`). It never relays mail — this API only reads and manages messages,
tags, and sessions that maelsink's SMTP listener has already stored.

The full machine-readable definition lives in `site/openapi.yaml` in this
repository; the content below is generated by hand from that same source of
truth so there is one conceptual definition, kept in sync.

:::note
`starlight-openapi` was evaluated for this page (see "Why hand-written?"
below) but its generated routes don't fit the fixed `/docs/rest-api-reference`
slug already wired into the sidebar, so this page is a hand-written reference
instead.
:::

## Authentication

When `api.auth.enabled` is `true` in server config, every `/api/v1/*` route
(except `/health` and `/version`) requires:

```
Authorization: Bearer <api.auth.api_key>
```

## Error envelope

Every error response uses the same shape:

```json
{ "error": { "code": "message_not_found", "message": "no message with id msg_xxx" } }
```

Common `code` values: `validation_error`, `ambiguous_id`, `message_not_found`,
`session_not_found`, `tag_not_found`, `tag_exists`, `confirmation_required`,
`invalid_query`, `invalid_request`, `attachment_not_found`, `internal_error`.

## Messages

### `GET /api/v1/messages`

List and filter messages.

**Query parameters**

| Param | Type | Description |
|---|---|---|
| `q` | string | Full-text search (FTS5 syntax, e.g. `subject:invoice AND NOT tag:spam`) |
| `from`, `to`, `subject`, `cc`, `bcc` | string | Substring filters on the respective header |
| `read` | boolean | Filter by read state |
| `has_attachments` | boolean | Filter to messages with attachments |
| `parse_warning` | boolean | Filter to messages with a MIME parse warning |
| `tag` | string (repeatable) | Filter by tag name |
| `tag_mode` | `any` \| `all` | Match any or all of the given `tag` params (default `any`) |
| `limit` | integer | Max results, capped at 500 (default 50) |
| `offset` | integer | Pagination offset (default 0) |
| `since`, `until` | RFC 3339 timestamp | Bound `received_at` |
| `sort` | `received_at_desc` \| `received_at_asc` | Default `received_at_desc` |

**Response `200`**

```json
{
  "messages": [
    {
      "id": "msg_01hz3k5xj8y3n1p9t3q7r0abcd",
      "from": "alice@example.com",
      "from_name": "Alice Example",
      "to": ["bob@example.com"],
      "to_names": ["Bob Example"],
      "cc": [],
      "bcc": [],
      "subject": "Welcome to maelsink",
      "size_bytes": 4213,
      "has_attachments": false,
      "attachment_count": 0,
      "received_at": "2026-08-17T09:15:00Z",
      "parse_warning": false,
      "read": false,
      "tags": ["onboarding"],
      "preview": "Thanks for signing up! Here's how to get started..."
    }
  ],
  "total": 1,
  "limit": 50,
  "offset": 0
}
```

### `DELETE /api/v1/messages`

Delete every message. Requires `?confirm=true`, otherwise returns `400
confirmation_required`.

**Response**: `204 No Content`.

### `GET /api/v1/messages/export`

Bulk-export the filtered match set (same filter params as list, minus
pagination) as a `.zip` of `<id>.eml` files.

**Response**: `200`, `Content-Type: application/zip`.

### `GET /api/v1/messages/{id}`

Get a message's full detail. `{id}` may be any unambiguous prefix of the
message id; an ambiguous prefix returns `400 ambiguous_id`, and a missing id
returns `404 message_not_found`.

**Response `200`**

```json
{
  "id": "msg_01hz3k5xj8y3n1p9t3q7r0abcd",
  "from": "alice@example.com",
  "to": ["bob@example.com"],
  "cc": [],
  "bcc": [],
  "subject": "Welcome to maelsink",
  "size_bytes": 4213,
  "has_attachments": false,
  "attachment_count": 0,
  "received_at": "2026-08-17T09:15:00Z",
  "parse_warning": false,
  "read": false,
  "tags": ["onboarding"],
  "preview": "Thanks for signing up! Here's how to get started...",
  "headers": [{ "name": "Content-Type", "value": "text/html; charset=utf-8" }],
  "text_body": "Thanks for signing up! Here's how to get started with maelsink.",
  "html_body": "<p>Thanks for signing up! Here's how to get started with maelsink.</p>",
  "attachments": [],
  "raw_size_bytes": 4213,
  "session_id": "sess_01hz3k5xj8y3n1p9t3q7r0abcd"
}
```

`session_id` is omitted for messages saved outside a tracked SMTP session.

### `DELETE /api/v1/messages/{id}`

Delete a single message. **Response**: `204 No Content`.

### `PATCH /api/v1/messages/{id}/read`

Mark a message read or unread.

**Request body** (optional; an empty body marks it read)

```json
{ "read": false }
```

**Response**: `204 No Content`.

### `PATCH /api/v1/messages/{id}/tags`

Add and/or remove tags on a message.

**Request body**

```json
{ "add": ["important"], "remove": ["onboarding"] }
```

**Response `200`**: the updated `MessageSummary` (same shape as one entry of
`GET /api/v1/messages`).

### `GET /api/v1/messages/{id}/raw`

Returns the raw RFC 5322 source. **Response**: `200`,
`Content-Type: message/rfc822`.

### `GET /api/v1/messages/{id}/export`

Downloads a single message as `<id>.eml`. **Response**: `200`,
`Content-Type: message/rfc822`, `Content-Disposition: attachment; filename="<id>.eml"`.

### `GET /api/v1/messages/{id}/attachments/{attId}`

Downloads one attachment or inline image. **Response**: `200`, the raw bytes
with a matching `Content-Type` and `Content-Disposition: attachment;
filename="<filename>"`. `404 attachment_not_found` if either id doesn't
resolve.

## Stats

### `GET /api/v1/stats`

Server-wide message statistics.

```json
{
  "total_messages": 42,
  "total_size_bytes": 1048576,
  "unread_count": 5,
  "attachment_count": 7,
  "parse_warning_count": 0,
  "oldest_received_at": "2026-08-01T12:00:00Z",
  "newest_received_at": "2026-08-17T09:15:00Z"
}
```

## Tags

### `GET /api/v1/tags`

List every tag with usage stats.

```json
[
  { "name": "important", "color": "#e11d48", "count": 3, "last_used": "2026-08-17T09:15:00Z" },
  { "name": "onboarding", "color": "#2563eb", "count": 1, "last_used": null }
]
```

### `POST /api/v1/tags`

Create a tag.

**Request body**

```json
{ "name": "important", "color": "#e11d48" }
```

**Response**: `201` with the created tag (same shape as one `GET /api/v1/tags`
entry). `409 tag_exists` if the name is taken; `400 validation_error` if
`name`/`color` are missing.

### `PATCH /api/v1/tags/{name}`

Rename and/or recolor a tag. At least one of `name`/`color` is required.

```json
{ "color": "#16a34a" }
```

**Response `200`**: the updated tag. `404 tag_not_found` if `{name}` doesn't
exist.

### `DELETE /api/v1/tags/{name}`

Delete a tag (tagged messages are kept, just untagged). **Response**: `204 No
Content`.

### `DELETE /api/v1/tags/{name}/messages`

Delete a tag *and* every message tagged with it. **Response**: `204 No
Content`.

## Sessions

### `GET /api/v1/sessions`

List SMTP/shell sessions.

**Query parameters**: `status`, `client_ip`, `limit`, `offset`, `since`,
`until`, `sort` (`started_at_desc` | `started_at_asc`, default
`started_at_desc`).

```json
{
  "sessions": [
    {
      "id": "sess_01hz3k5xj8y3n1p9t3q7r0abcd",
      "client_ip": "127.0.0.1",
      "client_helo": "client.example.com",
      "started_at": "2026-08-17T09:14:58Z",
      "ended_at": "2026-08-17T09:15:00Z",
      "status": "completed",
      "message_id": "msg_01hz3k5xj8y3n1p9t3q7r0abcd"
    }
  ],
  "total": 1,
  "limit": 50,
  "offset": 0
}
```

### `DELETE /api/v1/sessions`

Delete every session. Requires `?confirm=true`. **Response**: `204 No
Content`.

### `GET /api/v1/sessions/{id}`

Get a session with its full transcript. `{id}` may be an unambiguous prefix.

```json
{
  "id": "sess_01hz3k5xj8y3n1p9t3q7r0abcd",
  "client_ip": "127.0.0.1",
  "client_helo": "client.example.com",
  "started_at": "2026-08-17T09:14:58Z",
  "ended_at": "2026-08-17T09:15:00Z",
  "status": "completed",
  "message_id": "msg_01hz3k5xj8y3n1p9t3q7r0abcd",
  "transcript": [
    { "direction": "recv", "line": "MAIL FROM:<alice@example.com>", "position": 3 }
  ]
}
```

### `DELETE /api/v1/sessions/{id}`

Delete a single session. **Response**: `204 No Content`.

## Meta

### `GET /api/v1/health`

Never requires authentication.

```json
{ "status": "ok", "db": "ok", "smtp": "listening" }
```

Returns `503` with `status: "degraded"` / `db: "error"` if the database is
unreachable.

### `GET /api/v1/version`

Never requires authentication.

```json
{ "version": "1.0.0", "commit": "a1b2c3d", "build_date": "2026-08-17T00:00:00Z", "go": "go1.26.4" }
```

## Why hand-written?

`starlight-openapi` renders each OpenAPI operation as its own page under a
plugin-owned sidebar group and route base (e.g. `/api/<schema>/operations/...`),
generated from `starlight({ plugins: [...] })`, not as a single page at an
arbitrary pre-existing slug. Since this project's sidebar already reserves a
fixed single-page slot — `{ label: 'REST API Reference', slug:
'docs/rest-api-reference' }` — adopting the plugin would mean replacing that
sidebar entry with the plugin's own generated tree, which conflicts with
"don't touch the sidebar array" for this milestone. This page is generated by
hand instead, kept as one source of truth with `site/openapi.yaml`.
